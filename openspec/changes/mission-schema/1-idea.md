# Idea: mission schema — one ladder, five rungs, gates declared where the ladder lives

> Parent idea: none

As a human grantor of missions I need one schema carrying the whole
ladder with its human gates declared in the schema itself, so that every
project — code, shopping, game advice — rides the same bridge with the
same law.

Today two schemas blur the line between durable direction and value
slice: ramona-idea parents nothing mechanically, ramona-plan's four rungs
have no claim and no declared gates, filenames drifted in the wild
(`idea.md` beside `2-plan.md`), the word "job" reads transactional, and
the teaching that makes it all work lives in a global AGENTS.md that
drifts from the package that enforces it.

The direction: one `mission` schema, version 1 — idea → proposition (the
falsifiable Claim) → proposal (the contract: Done when, Scope, Out of
Scope, Guardrails) → plan (the method: Skills first, Workflow, Steps,
Verification, History) → execution (the ledger with receipts and the
Human verdict) — strict `N-name.md` filenames, `x-requires-approval`,
`x-sections`, and `x-lines` declaring the gates pi-openspec-gate
enforces, and the two-lane map (approvals down, evidence up) carried in
the schema description. The repo adopts it (config default, remedy line,
counter filename, latch phrase "action the mission"); the global copy is
the Human's to sync by rm + cp; the gate degrades gracefully until the
phase-gates mechanism ships, so ordering is safe. Hard limits: openspec
itself must keep loading the schema unmodified — unknown x- fields strip
silently there, the gate validates its own tags loudly; memory and gate
mechanics belong to their own slices, not this one.
