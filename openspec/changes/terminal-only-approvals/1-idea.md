# Idea: Approvals are terminal-only; the agent names the next act

## Pain

Two conversational latches let chat move the gate: a literal VALID reply permits the verdict-line flip, and "action/execute the mission" passes one unapproved source mutation — approval stops being a deliberate act. The assistant names the next grant only when a block forces it, so at every other pause the human hunts for the right command. The teaching still speaks missions, ladders, and rungs while the project schema is the six-step spec flow — two dialects for one law, down to the engine's own block reason teaching a schema the project no longer defaults to.

## Questions

- What counts as the approval surface once conversation is out — which terminal acts exactly (verbs, grant, confirm)?
- Flag or removal: is terminal-only a config switch (what default, what migration for installed vintages) or an unconditional change?
- What must the agent's end-of-turn reminder carry (change, waiting-on, exact command), and where is the duty taught so it cannot drift from the teeth?
- Does the vocabulary rename (ladder/rung → flow/steps) land in the same release — schemas, engine copy, block reasons, skill, protocol block?
- What happens to the mission schema and the mission-protocol skill: retire with this change, or keep as a second example?
- Which tests pin the new behavior (VALID latch dead, declaration latch dead, reminder duty taught)?
